# GradPilot 设计审计与改造说明

## 审计范围

本次检查覆盖 `/`、`/profile`、`/program`、`/story`、`/result`、`/batch` 和
`/library`，使用 390px、768px、1440px 三个视口检查真实页面，并结合无数据、
已有背景与项目数据两种状态。判断标准是：用户能否快速回答“我现在在哪、
下一步做什么、哪些内容会被复用、出错后从哪里恢复”。

## 主要问题

### 1. 入口过多，且两条工作流没有清楚区分

原界面同时提供首页四步流程、单项目分析、批量生成、装配工作台和嵌入在项目页里的
故事访谈。用户很难判断什么时候应该逐篇处理，什么时候应该使用项目装配。

改造后，导航按“工作区 / 单篇流程 / 效率工具”分组。首页直接展示当前背景、
申请项目和下一步，申请项目页负责完整的多项目装配，单项目分析明确标注为快速分析。

### 2. 首页更像宣传页，而不是工作台

大幅品牌横幅和文书示意占用首屏，但没有回答用户最关心的问题：当前做到哪一步、
还缺什么、应该继续哪里。

改造后，首页改为状态型工作台：显示背景、项目、故事、文书数量，给出唯一下一步
按钮，并列出当前申请进度和最近项目。

### 3. 移动端导航和步骤条重复

原移动端把全部导航横向塞入一行，同时保留第二条步骤导航。后面的页面入口在屏幕外，
也没有明显提示可以横向滚动。

改造后，移动端使用独立抽屉菜单，当前页面显示在顶栏；四步进度只在页面语境需要时
出现，不再与主导航重复。菜单支持遮罩关闭、Escape 关闭，并在关闭时退出键盘焦点。

### 4. 首次进入申请项目页时缺少引导

没有背景数据时，页面仍显示三张空表和一张工程化画布，用户看到的是系统结构，
而不是可执行任务。

改造后，空状态改为“建立背景 → 添加学校项目 → 生成文书”的三步引导，并只保留
一个主要入口。已有背景后才展示完整项目和故事管理区。

### 5. 术语偏系统内部，增加理解成本

“装配链路”“背景实例”“故事实例”“传统背景资料”等词更适合开发说明，不适合
申请者。界面现在优先使用“申请项目”“背景资料”“故事”“文书结构”等用户语言，
必要的关系说明放在辅助文案中。

### 6. 移动端操作区容易被遮挡

语音助手悬浮按钮会覆盖表单底部的固定操作栏；部分三按钮操作组在窄屏上过度压缩。

改造后，移动端语音按钮缩小并上移，普通表单操作栏改为两列网格，末尾奇数按钮独占
一行，避免按钮文字被压碎或互相覆盖。

### 7. 视觉层级平均，缺少明确焦点

页面大量使用相同的白卡、绿色和圆角，标题、说明、状态和操作之间差异不足，长时间
使用容易疲劳。

改造后，主色收敛为深绿，辅色只用于区分数据类别；卡片圆角统一为 8px，标题使用
更明确的字号层级，状态使用文字标签而不是只依赖颜色。装饰性内容从任务页移除，
保留在真正需要说明关系的位置。

## 实施边界

- 未修改 API、数据库结构、鉴权方式或生成流程。
- 未改变现有 Voice Agent、批量任务和版本管理能力。
- 所有新增交互仍使用项目现有 React、Next.js 和图标组件，没有引入新的 UI 依赖。
- 已通过 `npm run typecheck` 和 `npm run lint`，并在浏览器中检查桌面与移动端主要页面。

## 后续建议

1. 用真实申请材料完成一次从背景到草稿的可用性测试，记录每一步的放弃原因。
2. 为长表单增加明确的保存状态与离开提醒，避免用户误以为内容已经自动保存。
3. 为语音助手补充非麦克风场景的显式入口说明，并验证权限被拒绝后的恢复路径。
4. 若后续增加更多页面，应继续保持“当前任务优先、全局导航分组、移动端抽屉”的结构。
