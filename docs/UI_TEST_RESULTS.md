## 测试方法与边界

运行环境为 Node.js 24.22.3 / npm 11.9.0、Python 3.12。仓库原声明使用 Node.js 22 / npm 10、Python 3.13+；没有更改这些依赖约定。

浏览器检查使用生产构建生成的 HTML 与相同 JS/CSS 资源。托管预览启动器给 Next.js 传入不支持的 `--host` 参数，因此使用临时静态页面快照做布局与纯前端交互检查。该快照不作为交付项目的运行方式，不等同于完整 Next.js 服务联调。最终 ZIP 仍保留原有 `npm run dev` / `npm run build` / `npm start`。

没有可用的真实 DeepSeek API Key，因此未验证真实模型输出质量，也未在浏览器中跑通上传解析、三轮访谈、生成/审核/重写/下载/复制非空草稿及历史切换。后端原有模拟测试通过不能替代真实 API 验收。移动宽度检查为桌面浏览器内固定宽度 iframe，不是实体手机测试。

## 小组接入 API 后的验收表

用 `examples/ui/cases.json` 的两个案例分别执行，并把实际结果另存文件。

- [ ] 从背景输入开始，成功生成画像并进入项目分析。
- [ ] 结果正确显示优势、差距、写作建议；修改输入后旧分析隐藏。
- [ ] 完成三轮访谈，消息自动滚动，素材卡片更新。
- [ ] 发送失败保留回答；快捷键不重复发送；中文输入法选字时不发送。
- [ ] 生成中文大纲与英文草稿，检查内容忠于输入且不编造结果。
- [ ] 复制与下载草稿，核对与屏幕文字一致。
- [ ] 重写后查看旧版本，并返回当前版本；不混合不同类型的历史内容。
- [ ] 刷新恢复会话、加载另一条历史记录，核对资料一致。
- [ ] 测试超过 10 MB / 不支持格式的简历及错误 API Key。
- [ ] 在实际 Node 22 / Python 3.13+ 环境运行全部检查。
- [ ] 让另一位组员独立运行并记录实际交接经验。
